## Components

### 1. Video Processing Pipeline (Bash + ffmpeg + Whisper)

- `scripts/process_video.sh` — extracts audio from `.mp4` (ffmpeg — UNVERIFIED in this session, referenced in legacy memory) and transcribes it using Whisper (`.venv/bin/whisper`)
- `scripts/step3_analise_avancada.sh` — invokes external `axet-code` CLI using `prompts/analise_transcricao_avancada.md` as prompt template, generating AI-based advanced analysis/summary
- Input: `videos/*.mp4`
- Output: `output/*.txt` (transcript), `output/*_audio.wav` (extracted audio), `output/*_resumo_*.md` (AI summary), `output/logs/` (execution logs)

### 2. Dashboard (Node.js, vanilla, no framework)

- `dashboard/server.js` (458 lines) — HTTP server + SSE (Server-Sent Events), pure `http` module, no Express
  - Port: `const PORT = parseInt(process.argv[2] || process.env.PORT || "4545", 10)` — default **4545**, overridable via CLI arg or `PORT` env var
  - Endpoints (confirmed via grep):
    - `POST /telemetry` — receives telemetry events from pipeline scripts
    - `GET /events` — SSE stream broadcasting run events to connected dashboard clients
  - `http.createServer((req, res) => {...})` at line 320, routes parsed via `url.parse(req.url, true)`
  - `server.listen(PORT, ...)` at line 454
  - In-memory run tracking: `runs` object, `runOrder` array (no persistent DB)
  - Process management: spawns `scripts/process_video.sh` via `execSync`/`spawn`; `getChildPids()` / `killProcessTree()` for full process-tree termination on cancel
  - `checkStaleRuns()` — detects/cleans zombie runs
  - `broadcast()` — pushes events to all connected SSE clients
- `dashboard/app.js` (578 lines) — vanilla JS frontend, no build step, no framework
  - Connects to `/events` SSE stream
  - `applyEvent()` / `applyEventLocally()` — core event-to-UI-state reducers (highest connectivity per Graphify graph)
  - `loadInitialState()` — fetches current run state on page load
  - `renderRunCardInfo()`, `renderRunInfo()`, `createRunCard()`, `ensureRunCard()`, `renderStepCardsForRun()`, `syncActiveRunCards()` — UI rendering for active run cards
  - `renderHistory()` — renders completed run history
  - `STEP_ORDER` / `STEP_LABELS` — define pipeline step sequence shown in UI
- `dashboard/index.html` / `dashboard/style.css` — markup and styling

## Telemetry / Real-time Updates

- Pipeline scripts POST telemetry events to the dashboard server (`POST /telemetry`)
- Dashboard streams these events to connected browser clients via SSE (`GET /events`)
- Frontend (`app.js`) applies events locally to update run cards, progress bars, logs, and history in real time
