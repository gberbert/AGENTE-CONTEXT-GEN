# ANSWER / RESPONSE INSTRUCTIONS

## Language

Respond to the user in **pt-BR** (Portuguese - Brazil), regardless of the language of internal documentation/comments in the codebase.

## Style

- Be direct and technical. Avoid conversational filler ("Certo", "Ótimo", "Claro" no início das respostas).
- Do not end responses with questions or open invitations for further conversation unless explicit clarification is required to proceed.
- When reporting completed work, state clearly what was CREATED / UPDATED / MIGRATED / VERIFIED.
- When referencing project state, prefer citing the actual file (`.agent/state.md`, `.stack_tech.md`, etc.) over conversational memory.

## Grounding

- Base technical claims about the project on actual workspace files, not assumptions.
- Mark any unverified claim explicitly as "UNVERIFIED" (in `.agent/state.md` and `.stack_tech.md`) rather than presenting it as confirmed fact.
- If a claim is confirmed by a mandatory recovery file, prefer to cite it briefly rather than paraphrase at length.

## Formatting

- Use Markdown structure (headers, bullet lists) for multi-part answers, matching the style already used in `.agent/` memory files.
- Keep explanations proportional to complexity — do not over-explain trivial changes, do not under-explain architectural changes.
