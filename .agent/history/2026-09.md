## 2026-09-19 21:10–21:33 — PID-tracking + Cancel Run feature (COMPLETED)

**Problem:** `POST /cancel` endpoint only sent `SIGTERM` to the main bash script PID. Since `ffmpeg`/`whisper`/`axet-code` run in foreground without `setsid`, orphaned child processes (esp. Whisper's multiprocessing children) were not guaranteed to terminate.

**Solution implemented in `dashboard/server.js`:**
- Added `getChildPids(pid)` — uses `pgrep -P <pid>` to find direct children.
- Added `killProcessTree(pid, signal)` — BFS traversal of full descendant tree, killing leaves first, then parent.
- `/cancel` endpoint updated to call `killProcessTree(run.pid, "SIGTERM")` instead of a direct `process.kill()`.

**Validated:** Full manual start→cancel test with `videos/reef_teste_clip.mp4` (whisper `tiny`, pt). Confirmed via `ps`/`pgrep` that no orphaned processes remained after cancel; dashboard state correctly showed `status: "cancelled"`; run's own SIGTERM trap (in `process_video.sh`) correctly emitted the `run_end` event with `cancelled` status (not the `/cancel` endpoint itself — architecturally correct separation).

No changes needed to `scripts/process_video.sh` or `scripts/step3_analise_avancada.sh` — both already had `emit_run_pid`, SIGTERM traps, and cancelled-status handling in place.
